# JevClean 界面

React 本地浏览器界面。沿用用户指定的 PreVibe 默认浅色：48px 顶栏、320px 常驻分析侧栏（1100px 及以下为240px）和连续邮件主区。左栏与右侧分别滚动，窄窗横向访问完整双栏，侧栏和规则列表常驻；每条规则的详细描述独立展开。单一「开始分析」入口内部读取并调用 Jev；API、邮箱和语言配置各有独立设置页。一个应用入口，无新增路由服务或远程资源。

| 文件 | 职责 |
| --- | --- |
| [App.tsx](App.tsx) | 配置及草稿状态、设置分类、分析范围、同意项、轮询、选择、冲突处理、确认执行、核对与撤销 |
| [ConfirmationDialog.tsx](ConfirmationDialog.tsx) | 规则／手动确认共用的原生模态窗口、取消焦点和 Escape 行为；不授予执行权限 |
| [ManualPanel.tsx](ManualPanel.tsx) | 手动单一动作的数量／目标确认、已满足状态跳过及目标缺失修复；事件交回 App |
| [WorkspacePanels.tsx](WorkspacePanels.tsx) / [workspace-state.ts](workspace-state.ts) | 范围摘要、常驻操作条及纯本地搜索／选择派生；不授予执行权限 |
| [SelectedMailList.tsx](SelectedMailList.tsx) | 手动确认的实际对象清单、逐项检查，以及规则确认的跳过原因；规则确认不重复列出主执行集合 |
| [MailList.tsx](MailList.tsx) | 受控邮件列表，判断／执行分列；正文阅读和行内本地分析记录各自独立，不因详情连接失败阻止查看已保存证据 |
| [AnalysisDetails.tsx](AnalysisDetails.tsx) | 展示当时规则、条件／时间原始回答和完整概率表、程序结论及逐次调用；按需读取具名本地trace，缺失记录不重建、不调用IMAP或Jev |
| [locale.ts](locale.ts) / [strings.en.json](strings.en.json) | 中英文界面、已知应用提示与动作文案；保留邮件、规则内容与文件夹路径，不改模型输入 |
| [mail-copy.ts](mail-copy.ts) | 仅显示的完整句模板、结果筛选、判断／处理状态、已确认批次去向和已知错误解释；不修改模型输入、原始判断或执行资格 |
| [styles.css](styles.css) | 浅色系统字体、组件状态、宽列表与窄屏结构变换、焦点及减少动态效果 |
| [api.ts](api.ts) | 仅调用具名本地 API；会话令牌存 sessionStorage，凭据不由界面读回 |
| [main.tsx](main.tsx) | React 启动与样式入口 |

设置导航依次为「分析服务」「邮箱设置」「显示语言」「管理规则」「隐私记录」，默认进入「分析服务」。前三项分别呈现 API、邮箱和语言配置，不新增路由或服务。切换设置页及设置／主界面保留共享的未保存配置、密钥和规则草稿；开始分析自动保存有效修改。左栏文件夹、最近／全部范围、有效数量、已保存规则的勾选和发送文本同意自动保存；150ms 合并选择，串行提交具名 analysis-settings 接口，失败保留选择并提供重试。该接口不提交邮箱、密钥或规则内容；新增规则首次完整保存前只在草稿中改启用状态，自动保存仅发送已持久化规则标识。空文件夹选择可保存，但不能分析。设置页仍提供完整表单保存。

左栏只保留「选文件夹」「邮件范围」「整理规则」三个同级、同字体字号的分组标题，不再叠加「分析设置」「本次范围」。左栏常显全部规则的启用复选框、名称与动作；详细描述默认收起，由条内「展开／收起」按钮独立控制，不改变勾选状态。整理规则区仅保留「管理规则」入口，新增与编辑均在规则管理页完成。设置页显示完整条件，新增表单位于规则管理顶部，新规则 prepend。分析按钮在侧栏底部常驻；启动前校验 API、邮箱、规则和发送同意，并先只读检查所有启用动作。配置缺失不调用 Jev，分析前检查失败时进入「设置 → 管理规则」顶部修复区；保存并检查通过后返回邮件。邮件区只显示已确认的动作去向提示，不保留正常预检的折叠与重查按钮。核心 read-mail API 支持独立邮件头读取，但没有读取邮件或无 AI 首次读取的 UI 入口。

四个结果标签固定为「符合规则」「待查看」「暂不整理」「全部邮件」。命中由判断与未解决冲突派生，不因已处理、撤销或 noop 隐藏；未分类并入待查看，配置问题不冒充 AI 判断不足。未命中包括全局保留或全部普通规则明确不匹配；局部例外不否决其他命中。行内区分请求失败、判断不足和动作冲突。有效报告 bootstrap、分析完成及返回命中页默认选择 canExecute 记录；切换其他分类清除选择和搜索。搜索只匹配已加载主题／发件人，不发请求；搜索变化会移除不匹配的已选邮件，清空搜索不补选。工具栏保留已选数量，不再提供「查看已选」「清除选择」及筛选外选择计数。查看邮件不改变选择。

`ActionSelectionBar` 常驻邮件区上方，显示全部八个手动动作与固定名称「整理」，无选择时也保留工具栏。整理只在命中页、有效 AI 报告、有可执行选中项且非忙碌／确认时可用；点击仅打开规则确认弹窗。其他分类禁用整理，手动动作仍可检查并确认。手动操作不依赖 AI 门槛或语义摘要，但受账号、任务互斥和未知位置保护。规则与手动确认共用原生 dialog 模态窗口，背景不可交互；初始焦点在取消按钮，取消／Escape 返回触发焦点。规则确认显示实际执行数量、动作与目标及必要的删除／撤销说明，不重复列出「将按规则处理的邮件」；有排除项时仍可查看跳过原因。手动确认保留准备处理、将跳过、暂不能处理及逐封检查；检查请求失败直接显示在弹窗内，可重试或取消。不以按钮颜色授予执行权限。

多规则由核心统一合并，普通规则的例外仅约束本条，只有独立保留动作全局保护；最高优先级同级冲突显示选择入口。直接使用当前规则语义，不设旧版迁移确认或分析前拦截，不自动拆写规则。目标变化不使语义判断失效，保存检查后可复用结果；条件／动作／账号／范围或判断版本变化需重新分析。缺少或不匹配版本8语义摘要的报告不得按规则执行，不补造授权；手动处理和撤销仍可用。ManualPanel 修改目标清空旧计划，保留修复入口并要求重新检查；系统目标保存不提交其他草稿。

MailList 不自行发请求或修改邮箱，事件交回 App，由[本地服务](../local/AGENTS.md)与[核心模块](../core/AGENTS.md)验证。阅读区独立于筛选行集合，关闭／Escape 恢复触发按钮和右侧邮件区滚动位置；焦点自动避开顶部工具栏。纯文本正文绝不执行 HTML、下载附件或远程图片。AI 徽标只由原判断派生，手动操作不能改变它；兼容旧 mail-only 报告仍隐藏旧 AI 执行条件，不改变存储证据。

「最近整理」隐藏零计数，去向来自操作记录；异常项直接来自 CleanupSummary.issues，不从当前 report 推断其他批次失败。结果未知先只读刷新，不给盲重试入口。`Progress.operationIds` 只标识当前报告中与本批物理位置关联的行，不授予执行权限；仅这些行的 moving／restoring／uncertain 状态在处理或核对期间显示中性进度。已确认成功的行保持成功状态，其他批次的不确定行不被遮掩。列表和阅读区共用阶段文案；自动核对时隐藏刷新及临时异常清单，完成后仍不确定才显示黄色具体原因与刷新入口。重载通过 bootstrap／status 恢复同一阶段与行集合。整理／撤销的 Progress.phase 跟随真实阶段；operationTotal 保持本次邮件数，folderCheck 单独显示文件夹邮件头检查条数，不冒充操作数。最近一批恢复记录独立保存，后续分析不覆盖它。

分析元信息只显示时间与成功分析响应的 token 累计，不保证等于账单消耗。「分析记录」另逐attempt累计已知usage，缺失明确显示未知，不把失败视作零消耗；进程中断后的sending表示结果未记录，不表示仍在发送。工作区与设置页无底部隐私文案和快捷按钮；「设置 → 隐私记录」提供完整调用记录开关／清除及运行记录。

默认基本证据保存当时规则、去正文上下文的问题、原始回答／概率与调用状态。完整trace默认关闭，开启后仅保存实际请求／响应，最新批、7天、50 MiB、单响应1 MiB；界面说明个人信息、截断和缺失，不展示认证头或密钥。关闭或清除完整trace不删除基本结论与撤销。缺失证据不以当前规则或正文重建；查看本地详情不依赖正文读取成功。

失败分析可单封重试，最终资格由服务器判断：v8且有inputHash、未获得有效判断、未执行、7天内，同账号／规则／范围及实际输入不变。低把握或成功判断不能重试；重试可能消耗额度，并追加旧attempt而非覆盖历史。它不重试删除／移动，未知执行结果仍先只读刷新。详情文案需明确条件判断、时间判断和程序合并结论，局部例外不能显示成全局保留。

连接成功提示约5秒自动关闭；顶栏状态只表示本次进程对该账号和密码成功验证，不是持续 IMAP 连接。应用菜单退出调用已验证 shutdown，任务期间禁用。中英文仅翻译 UI 和已知诊断，不改变邮件、规则、文件夹、Jev 输入或摘要。

分析结束显示「分析完成」及本次邮件数；停止或中断保留实际状态，未得到有效判断另说明数量。整理只有最近批次全部确认成功才显示「整理完成」及处理数量，部分失败／未知显示实际数量和提醒。两类任务结束提示保留到手动关闭、下一项操作或新的提示；其他普通通知仍约5秒自动关闭。重载后接续中的任务由现有状态轮询在完成时发出同样提示，不在每次打开历史报告时补发成功通知。提示不改变分类、执行或撤销资格。

验证命令为 `npm run check` 与 `npm run test:ui`；界面文案遵循[文案对照表](../../docs/ui-copy.zh-CN.md)：名称2至4字，必要说明每句最多20字。`locale.ts` 的固定诊断文案映射只影响显示，不回写原始记录；规则条件及原始请求、返回保持完整。新默认规则只改展示名称，不重命名已保存规则。界面测试使用合成邮箱／模型及真实本地 HTTP，端口可由 JEVCLEAN_UI_PORT 覆盖。各轮固定工作区、规则呈现及确认弹窗的验证分别见[实施记录](../../docs/product-design-review-2026-10-06.md#12-实施记录)，旧通过数量不证明新流程。设计来源：[PRODUCT.md](../../PRODUCT.md)、[DESIGN.md](../../DESIGN.md)。仅使用本地系统字体与打包图标。
