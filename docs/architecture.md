# JevClean 架构

## 运行边界

```
系统浏览器 → 127.0.0.1 本地 HTTP → MailService → 用户 IMAP 服务器（TLS）
                                    ├── Jev 官方 HTTPS API
                                    └── 加密本地文件 + 系统凭据库
```

没有项目云端、数据库服务或 Electron。一个 Node.js 进程既提供静态界面，也提供具名本地 API；React 负责用户配置和确认。浏览器不能直接建立普通 TCP IMAP 连接，因此本机执行层是必要的；不用增加云端中转。macOS 包含独立官方 Node 24 LTS、打包后的 JS、静态网页和系统凭据库原生绑定。轻量 AppKit 启动器响应系统打开／再次打开事件，不嵌入网页；再次打开通过 Node 单实例入口唤起浏览器，服务退出后启动器也退出。

## 判断流程

规则包含 `id/name/description/enabled/action`，仅移动动作另含 `targetMailbox`。每条规则一个枚举动作，不接收模型生成的命令。配置另含可选的 `actionFolders` 系统文件夹映射。开启的预设和自定义规则没有不同业务分支：每封邮件使用一个 state，每条启用规则生成两个 choice 问题，在一次 Jev 请求中并行回答。

0. 当前直接使用局部例外／独立保留规则语义，无版本迁移确认。在任何正文读取或 Jev 调用前，检查全部启用规则的动作、所有来源与目标文件夹及 MOVE／UIDPLUS 能力。目标按用户映射、服务器明确标识、唯一常见名称识别（包括「已删除」）的优先级解析；多个名称候选需要用户选择，不模糊匹配或自动创建文件夹。预检只使用 LIST／EXAMINE，不尝试写入；未来权限／网络变化仍由实际执行校验处理。失败保留已有报告，不调用 Jev。
1. 按勾选的多个文件夹 EXAMINE 获取 UID 列表。`scanLimit` 为正整数时，分批只 FETCH UID／INTERNALDATE，在所有选中文件夹中按服务器收件时间选取最近 X 封；同时间用文件夹顺序和 UID 降序稳定打破平局。无法确认时间时在调用 Jev 前停止。`null` 表示全部邮件。只有范围内邮件通过 PEEK 读取状态和正文，再逐文件夹分析；重开文件夹核对 UIDVALIDITY，记录 ID 包含文件夹索引，避免同 UID 串邮件。
2. 代码提供当前时间、时区与收件年龄，隐藏可识别口令、验证码、链接路径和内嵌 base64 图片数据。主题、发件人地址及纯文本正文会提交给 Jev。
3. 第一个 choice 只判断条件及非时间例外，所有规则使用 match / not_match / uncertain；普通规则的排除／保留例外属于本条 not_match，不决定其他规则。动作与目标字段不发送给模型，动作由本地已保存规则确定。第二个 choice 选择适用的时间依据：无需时间条件、规则中的收件年龄、正文中的实际截止时间或无法确定。直接回答 uncertain 或条件选项概率低于 0.80（含 not_match）均标为本条不确定，保留原始选项和概率，不伪造模型回答。
4. 普通日期、相对天数和时长由代码生成候选，Jev 选择其含义，代码核对是否已结束。自然语言规则中的数字／常用中文数量及分钟、小时、天、周、月、年沿用同一通用时间枚举；月和年按日历计算，末日裁剪。年不明确、无法解析、证据不足或候选过多时保留。日历日期按机器本地时区的日末处理。
5. 条件及时间均达到 0.80 且时间核对通过时形成完整匹配。只有独立 action=keep 规则具有全局保护能力：完整匹配则保留，条件或时间不确定则 review；明确不匹配或已证明未满足时间条件才退出。普通规则的局部排除或不确定不否决其他完整匹配。普通完整匹配取最高优先级：删除 > 垃圾邮件 > 移动 > 归档 > 全部标记动作。同级相同动作／目标合并，不同动作或目标产生冲突；较低级别不能打破最高级别冲突。用户只能从该级别已完整匹配的选项中选择，不能放行证据不足的结果。初次分类和修改目标后的重建共用 `rules.mergeRuleActions`，分数取支持动作的最佳规则。没有完整匹配时，有不确定则 review，全部明确不匹配则 keep，缺少保留依据不自动授权动作。
6. `category/eligible/reason` 保存 AI 合并后的语义判断；独立 `execution` 表示 ready、blocked 或 noop，带执行问题代码与提示。目标缺失、协议不足和已在目标状态都不改写 AI 分类或理由。只有完整匹配、可执行且未执行／未完成的记录可按规则处理；选择框本身不依赖 AI 判断。Gmail 使用 All Mail 归档仅允许 INBOX 来源。

固定模型 `jev-1.13.0`，动作门槛为选中选项 probability ≥ 0.80。Choice 的 confidence 是从概率计算的统计量，不是独立的第二份正确性证明；原始 confidence 仍记录但不重复设门槛。该候选门槛经有限真实／合成样本和原始回答重放检查，尚未完成广泛邮箱准确率校准；后续还有明确选中、确认与可撤销移动，不能等同准确率或自动删除许可。

报告区分原始模型选项／分布与程序最终判定，并保留具体拦截原因和时间问题回答。新记录包含发送时的基本快照及调用尝试；旧记录中缺失的字段不倒推、不补造。策略摘要升级后旧候选失效，原报告仍能查看，旧移动凭据仍可撤销。版本 8 的新提示尚未经过真实模型质量检查；详见[判断排查说明](classification.md)。

单封正文超过 24,000 字符、读取超过 128 KiB 或不完整时不产生可执行动作；这些工程限制不放进筛选界面。草稿和已标记删除项不参与自动规则处理。星标、附件和已回复状态交给自然语言规则，不使用隐藏业务关键词保护。

## 独立读取与手动处理

`read-mail` 是内部独立邮件头读取能力，当前界面已移除单独读取入口，统一由 scan 完成读取和分析。该接口只要求当前 IMAP 配置，不要求 Jev 密钥、规则或文本发送同意。和分析共用多文件夹最近 N／全部范围选取，但只 FETCH 邮件头、标记、收件时间及 MIME 结构，不下载正文。没有既有判断的记录是 `unclassified`。同一账号、语义摘要、位置和相关标记不变时保留已有判断，读取本身不生成 AI 授权；正文预览由用户单独打开。

`manual-check` 只接受所选本地记录 ID、已知单一动作和移动目标，不接受模型概率或任意 IMAP 命令。检查当前账号、实际位置／UIDVALIDITY／指纹、该动作需要的能力和目标；已满足状态列为 noop，缺失目标提供配置入口。返回进程内、一次性的确认计划，含数量和目标。`manual-execute` 仅接收计划 ID，核对账号、当前列表快照和系统映射，再进入共用执行器；重启、列表变化或目标改变后须重新检查。规则变化本身不禁止手动操作。

`MailRecord.action/targetMailbox/category/verdicts/probability` 仍保存原 AI 判断及规则计划；实际动作另存 `operation.source/action/targetMailbox`。手动执行不改写模型证据，也不把“保留”改成“删除”。核对、预览、汇总和撤销读取实际操作。连续手动动作使用已确认的当前位置，记录这次实际原始标记／来源；撤销仅撤销最近批次。`action-folders` 仅合并系统目标映射，不提交规则、密码或密钥草稿。上一批仍有未知结果时禁止覆盖其恢复记录；重新读取列表仍阻止这些邮件，只读刷新后更新状态而保留新分类。

## 本地 HTTP

端口由系统分配，只监听 127.0.0.1。启动 URL 的 fragment 携带随机会话令牌，前端存入 sessionStorage 后从地址栏移除；令牌与邮箱／Jev 密钥无关。所有 `/api/` 调用需要专用 header，并校验 Host 与存在时的 Origin；不提供 CORS。请求体最多 256 KiB，操作参数使用 zod 验证，静态文件 realpath 必须位于构建目录内。CSP 拒绝远程脚本与前端网络资源。

路由只暴露具名操作：读取配置／邮件列表／结果／进度／日志，保存配置，测试邮箱／Jev，动作预检，分析／取消／重试失败分析，预览，读取／清除本地完整调用记录，动作冲突选择，执行／撤销，最近操作结果核对，清除凭据／记录和退出。`analysis-trace` 验证当前报告与邮件标识，仅返回对应本地记录；`retry-analysis` 只接受报告、邮件标识及明确发送同意，由核心重新验证资格。没有通用文件或网络访问 API。bootstrap 另含 `mailConnection`：只记录当前进程内，最近一次成功连接的账号身份、密码匹配和验证时间；保存密码本身不代表已验证，重启清空该状态，空闲不保留 IMAP 长连接。该字段不返回密码。连接操作失败后清空验证状态，界面完成操作时刷新 bootstrap。

bootstrap 返回当前任务进度与独立最近操作汇总，读取、分析、移动、恢复及核对期间每 1.2 秒轮询；重新加载页面仍可跟踪当前任务。任务互斥，执行期间不能修改配置或重复执行。`execute` 与 `refresh-actions` 是唯一的规则执行与结果核对 HTTP 入口；`resolve-conflict` 只接受报告内的匹配选项标识。`check-actions` 返回文件夹、每组动作的准备状态及更新后的报告；只读检查，不调用 Jev。bootstrap 的 `preflight` 是当前进程、当前执行配置下的最近预检，重启不伪造检查成功。

## 数据与恢复

`settings.enc` 存邮箱、规则、分析数量、界面语言、规则语义确认、完整诊断开关及两组凭据；`report.enc` 存最近分析的范围、主题／发件人、判断和基本分析快照；`last-action.enc` 独立存最近操作批次和服务器目标 UID、动作、目标文件夹及标记操作前的原始布尔值。基本快照记录当时规则／问题／原始概率／合并结论、inputHash 及各次调用状态和已知用量，剔除正文上下文，不存正文或服务响应原文。正文阅读仍需按需访问 IMAP；独立分析详情不依赖该预览请求，不用重建预览冒充历史请求。

`recordedEvaluator` 在发送前记录实际请求的摘要和基本快照；开启 `detailedDiagnostics` 才把同一序列化请求及逐次响应文字另存于 `diagnostics/` 的加密文件。认证头和密钥不进入调用记录。完整记录仅保留最新批次、最长 7 天、总量 50 MiB，单次响应上限 1 MiB；截断明确标识，该回答不授予执行资格。保存失败停止分析；失败、取消、超时、无效响应及自动重试分别留证，收到的 usage 按 attempt 记录，缺失为未知。到期清理在应用启动及访问时触发，关闭期间到期则下次启动处理。关闭开关或清除完整记录不删除基本判断或撤销；清除全部报告则一并删除。

`retry-analysis` 仅重试当前报告中尚未获得有效判断、未处理并有 v8 inputHash 的记录；同账号、语义摘要和分析范围、原报告不超过 7 天是前提。重试先只读核对 UIDVALIDITY、指纹和按原分析时间构造的实际输入摘要，输入变化拒绝调用。成功或低概率判断不属于请求失败，不能借重试重复抽取答案。重试追加旧 attempt 序列，保留原始失败，不覆盖成功邮件或最近操作凭据；请求仍使用用户的 Jev 额度。旧报告没有摘要则只能重新分析，不能补造历史输入。

`settings.language` 可选 `zh-CN` / `en`，缺省由界面按中文展示，保存时写入加密配置；它不进入策略摘要或 Jev 输入。`src/renderer/locale.ts` 和本地英文文案表仅翻译界面及已知应用提示；邮件、规则标题／描述、文件夹路径等用户内容保持原样。语言草稿不使候选过期，其他影响判断的配置仍沿用旧报告保护。

随机 32 字节 AES-GCM 钥匙存系统凭据库，文件用不同 IV、认证标签和版本头加密，先写临时文件再替换。Unix 目录 0700，文件 0600。钥匙不存在且已有加密文件时拒绝生成替代钥匙。Linux 只接受持久 Secret Service，Windows／Linux 尚待实机验证。

语义摘要 `judgmentHash` 含账号、开启规则的条件与动作、分析范围、门槛及模型，不含界面语言、完整诊断偏好或文件夹目标；`policyHash` 另包含目标以界定执行预检缓存。修改系统映射或移动目标会暂停相关执行，`check-actions` 复用已有逐条判断更新目标与动作冲突，不重新调用 Jev。修改条件、动作、账号或分析范围仍须重新分析。实际 Jev 条件问题不包含动作字段或移动目标名称。当前摘要版本为 8，定义局部例外／显式全局保留语义；版本变化同时使旧完整摘要和语义摘要失效，缺少或不匹配当前语义摘要的报告不能通过补写摘要或重建目标获得执行资格。手动计划授权与独立最近操作撤销不依赖此版本。

按规则执行前核对语义摘要、门槛及相关标记变化；手动路径以明确确认的用户计划授权，忽略规则摘要和概率，不伪造分类。两者共同核对账号、UIDVALIDITY、指纹；所有执行目标重新解析，和已检查的记录目标不一致时要求重新检查配置。所有目标在命令发出前解析并核对，意图与方向先落盘。删除、归档、移动、垃圾邮件使用 UID MOVE；已读／未读与星标使用单一标记的 UID STORE，并保存原始值，再只读 FETCH 核对。每封保存并更新进度，不调用 COPY+广域 EXPUNGE 降级。

完整 UIDPLUS 凭据直接确认结果；缺少凭据或命令结果未知时，先标记位置不确定，并自动只读核对一次。`refresh-actions` 可再次核对最近批次，不受分类规则或后续分析的变化影响，但必须使用原账号。逐文件夹 EXAMINE，通过 SEARCH ALL 枚举 UID，再分批 FETCH UID／ENVELOPE／INTERNALDATE／FLAGS 获取位置和标记，严格按现有邮件指纹匹配。部分服务商的 Message-ID HEADER 搜索存在漏匹配，不能用其空结果证明原位置不存在，因此核对读取这两个位置的邮件头，不读取正文、不调用 Jev、不执行任何 MOVE。只有原 UIDVALIDITY 一致、邮件身份完整且唯一、原位置零匹配、目标位置唯一匹配时，才补齐目标 UID／UIDVALIDITY 并确认完成；唯一原位置则确认未清理或恢复完成，恢复后的原 UID 必须更新。已有目标 UIDVALIDITY 变化、重复指纹／副本、两处均有或均无匹配时保持不确定。标记动作只接受原 UID／身份／UIDVALIDITY 一致且原始标记已记录的唯一邮件，再比较目标值和原始值，不能把未知原始值当成可恢复凭据。核对时间、各动作完成数和汇总由加密最近操作记录持久化，日志只记汇总数字。 动作进度另携带当前显示报告中的物理关联行标识 `operationIds`，仅供界面展示，不授权执行。处理中及自动核对期间，相关不确定行显示中性阶段文案；已确认成功行不回退，不关联的行不被任务状态遮掩。核对完成仍未确认才显示具体原因和刷新入口。核心通过可选诊断回调记录固定原因枚举、数量、核对耗时及启动／完成／失败事件；日志不记记录标识、邮件内容、账号、文件夹或第三方原始响应，诊断失败不影响动作结果。

撤销按最近批次的目标 UID 移回原文件夹，或仅恢复记录的原始标记，不依据已改变的分类规则。标记动作的目标状态被外部改动，或原文件夹 UIDVALIDITY 改变时拒绝覆盖。恢复凭据独立于最近分析，因此再次扫描或重启仍可撤销。重启时中断状态统一变为位置不确定，可通过只读结果核对补齐凭据；仍无法确认时去原邮件客户端核对。新一批实际操作覆盖上一批的撤销入口；已移动的邮件仍可在原客户端手动恢复。

配置只按当前契约读取，不转换旧单文件夹字段、规则描述或规则作用范围标记。首次配置默认最近 100 封；保存的规则原样读取，默认预设不会覆盖现有描述或补回已删规则。规则未指定动作时采用表单默认删除动作。报告必须包含文件夹列表；缺少语义摘要的报告不会自动补写或恢复执行资格，须重新分析。进程中断后的不确定操作及独立撤销记录仍按真实凭据恢复，不受这次移除版本兼容影响。

`operations.log` 最多约 512 KiB 后轮换，保留一份旧文件，界面最多读取最新 100 条。只有应用事件、汇总数字、模型和状态进入日志；不记录账号、主题、正文、密钥或第三方原始错误。最近报告替换旧报告，避免无界历史积累。

## 验证边界

本地 TLS IMAP 测试验证协议，DI 的虚构邮箱／模型验证 HTTP 和界面。实际系统凭据库及打包后的官方运行时另行检查。`scripts/check-quality.ts` 只在显式提供 key 时发送 36 个预先标注的合成样本到真实 Jev；版本 8 新提示及新增简历样本未执行真实模型检查，参考标签也尚未经用户逐条核对。本轮实现的最终全量检查与安装验收待单独记录，不沿用旧轮次通过数量。测试服务器位于 tests 内，不是生产的演示回退模式。

## 跨报告的物理邮件身份

报告同步以账号一致为前提，核对文件夹、UIDVALIDITY、UID 的完整位置及指纹；指纹不是唯一邮件身份。可选 `MailRecord.operationLocations` 保留当前操作链里已经证明的原／目标／恢复位置，解决 MOVE 或撤销后 UID 变化而新报告仍指向旧位置的问题。旧记录仍可用完整来源及目标回执参与匹配，缺字段时不猜测身份。

未知结果仅阻断确切身份；缺 MOVE 回执时，对预期目标中符合身份信息的候选保守阻断，但不把候选当作已证明的操作对象，不覆盖新列表观察到的位置。最近操作意图已保存而旧报告仍 pending 时，重读也不能重新放行。只读核对或恢复确认后才更新可执行状态。

## 界面解释边界

`renderer/mail-copy.ts` 将原始判断和执行状态转换为通俗显示，不更改 Jev 请求、门槛、配置摘要或执行资格。「符合规则」筛选由原判断及未解决冲突派生，不因完成、撤销、未知操作结果或已满足目标而隐藏邮件；执行资格仍独立检查。「待查看」合并未分类，并区分请求失败、AI 证据不足、全局保留不确定和同级冲突。「暂不整理」包括全局保留及全部普通规则明确不匹配的邮件，不把局部例外显示成全局否决。`CleanupSummary.reportId`、`destinations` 与可选 `issues` 取自独立最近操作记录，不从当前列表或 AI 原因猜测。去向只汇总已确认完成的操作，不从当前配置推断。文件夹名按原值展示。`AnalysisDetails` 展示本地历史快照、原始回答及调用过程，缺失字段明确说明；查看详情不调用邮箱或 Jev，不因缺少旧证据自动付费重跑。

## 整理进度

整理／撤销可能在缺少回执时进入只读 `checking`。进度中的 `processed/total` 是该阶段邮件数，`operationTotal` 保持本次操作数量；`folderCheck` 单独携带当前文件夹名称、已查条数与总条数。文件夹头信息查询不代表新的分析或邮件操作；UI 跟随实际阶段，菜单栏只接收邮件级计数，不包含文件夹路径及列表条数。

## 分析区自动保存与 macOS 菜单栏

`analysis-settings` 仅接受文件夹、数量／全部范围、已启用规则标识和 `analysisConsent`；持有核心任务锁后合并到已有配置，保留密码、密钥和规则内容。空文件夹选择可持久化，scan 在正文和模型调用前拒绝空选择。同意项缺省为 false，不进入判断摘要或 Jev 输入；发送文本仍需 scan 请求明确同意。界面合并并串行保存，失败保留草稿和最新选择，提供重试。新增规则尚未完整保存时，偏好接口仅提交已持久化规则标识；新规则启用状态留在草稿，完整设置保存或启动分析时一并保存。接口不能借规则勾选创建规则或提交密钥。

AppKit 启动器保留 NSStatusItem 图标，提供状态、打开、重启和退出。精简的认证 GET `runtime` 只返回 phase／processed／total／busy／language；busy 来自核心实际任务锁，独立于进度快照。状态请求失败时禁用重启／退出；执行控制前 shutdown 再核验锁，不强杀正在工作或无响应的服务。关闭浏览器不退出后台。菜单栏和双击主动打开使用当前已验证的回环会话，首次 no-open 只影响首次显示；重启使用既有数据目录。

## AI 优先工作区

`App` 持有请求、草稿及执行门禁；`workspace-state` 仅派生当前列表本地搜索和完整选择集合，`WorkspacePanels` 显示范围与选择条。`MailList` 把 AI 判断、执行准备、实际操作分别显示，正文阅读与本地「分析记录」独立，均不改变选择。`AnalysisDetails` 只展示已保存证据，完整记录通过具名本地 API 按需读取；失败重试事件交给 App，再由服务端检查。`ConfirmationDialog` 通过原生 `showModal()` 提供共用模态与取消交互；执行和焦点返回仍由 App 管理。`SelectedMailList` 用于手动确认逐项检查及规则确认的排除项，不再重复列出规则主执行集合；手动实际资格仍来自服务器 `ManualPlan`，更换目标清空旧检查，不能复用旧计划。

设置将 API、邮箱和语言拆为独立页面，导航依次为「分析服务」「邮箱设置」「显示语言」「管理规则」「隐私记录」，默认配置API。App 继续持有同一份全局配置与密钥草稿；页间切换不清空草稿，保存及返回邮件的原有语义不变，不增加路由或服务。工作区左栏为常驻 320px（窄窗口 240px），全量显示文件夹、范围、规则与同意，内容独立滚动，启动分析在侧栏底部。右侧邮件区独立滚动；侧栏和规则列表常驻，规则描述独立折叠；不提供折叠侧栏或独立读取按钮。左栏只有文件夹、范围和过滤规则三个同级分组标题。窄窗口通过水平滚动保留双栏。

`ActionSelectionBar` 常驻邮件上方，显示八个手动动作和固定「整理」。无选择、任务中或确认中禁用；「整理」另要求处于命中规则页、有效 AI 报告及可执行选择。规则与手动确认使用原生 dialog 模态窗口，背景不可交互；初始焦点在取消，取消／Escape 关闭并返回触发焦点。规则确认显示实际数量、动作、目标及必要提示；手动确认仍由 `ManualPlan` 授权并保留逐项检查，不以按钮颜色替代服务器验证。有效分析初次加载、完成或返回命中页时默认选择 `canExecute` 的邮件，用户可取消；切换其他分类清除选择与搜索。本地主题／发件人搜索变化会从选择集合移除不匹配记录，清空搜索不补选；工具栏仅保留已选数量，不设查看已选或清除选择路径。`MailList` 在邮件区内部保存和恢复滚动位置及焦点。

邮件区的预检状态只显示动作去向，失败修复集中于设置中的规则页；分析前检查失败时自动打开，保存检查成功后返回邮件。分析元信息仅显示时间与成功分析响应的 token 累计，不等同账单；详情逐次显示已知 usage，失败尝试无 usage 时显示未知。API `apiCalls` 继续保留但不在元信息区展示。页面底部隐私文案与快捷按钮移除，设置中的隐私与记录能力保留。受限的失败请求重试已实现；增量分类、恢复尚未读取的整个范围、小样本规则试验和大邮箱优化仍是独立后续工作。
