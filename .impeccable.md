## Design Context

Individuals periodically organizing a personal IMAP mailbox, including non-programmers. The priority is “understand first, then act with confidence.” The user explicitly specified an AI-first flow on 2026-10-07: configure API, language and mailbox; choose folders, range and filtering rules; start analysis; inspect categories and organize. Manual controls remain available for loaded mail, independent of AI confidence and rule-policy freshness. Preserve the local process, encrypted credentials, consent, explicit confirmation, identity validation and latest-batch undo.

The visual reference is the PreVibe desktop client default light style, selected on 2026-10-06. Its palette and composition are recorded in DESIGN.md and docs/product-design-review-2026-10-06.md; no separate local checkout is required. Use #edf1f5 ground, #f7f9fc surface, #e8edf3 secondary surface, #1f2937 text, #596579 muted text and #424a57 primary buttons. Preserve JevClean branding; do not copy PreVibe business flows, logo or native traffic lights. Local system font stack only.

Settings has separate 分析服务, 邮箱设置, 显示语言, 管理规则 and 隐私记录 pages in that order, defaulting to 分析服务. API, mailbox and language are not combined into one page. Switching pages preserves the shared configuration and credential drafts; Save and Return to mail retain their existing semantics, without new routes or services.

Use a 48px header, permanent 320px analysis sidebar and continuous mail workspace. At <=1100px the sidebar is 240px; the two-pane workspace is at least 760px and can scroll horizontally in narrow windows. Sidebar content and mail pane scroll independently. The sidebar and rule list remain visible. Use matching typography for Choose folders, Mail range and Filtering rules; remove the extra Analysis settings and Current scope headings. Every rule title, checkbox and action stays exposed; detailed descriptions start collapsed, with independent Expand/Collapse buttons inside each rule. The filtering section only links to Manage rules; adding and editing occur on that page, where complete descriptions remain visible. New rules are prepended. The sole “开始分析” button stays at the sidebar bottom, reads the configured scope and calls Jev without changing mail. Remove separate read-mail and dual-path UI; the internal header-only API remains.

Use exactly four result tabs: 符合规则, 待查看, 暂不整理, 全部邮件. Matched membership does not change with operation status; unclassified records join review. Non-matched also includes keep judgments, whose reason stays visible. Valid report loading, analysis completion and returning to Matched select executable matched records; users may deselect. Switching other tabs clears selection and search. Changing local search deselects records that no longer match; clearing search does not select them again. Keep the selected count, but no View selected, Clear selection or hidden-selection controls.

The mail-top toolbar permanently exposes all eight manual actions plus fixed-label “整理”. Organize is enabled only in Matched with a current report and executable selected subset; other tabs show it disabled. It opens a native dialog requiring explicit confirmation. Rule confirmation summarizes actual counts, actions and destinations without a duplicate main-mail list; excluded counts and reasons remain when needed. Manual actions use the existing checked plan and keep per-message checks. The modal makes the background inert, initially focuses Cancel, and restores trigger focus after Cancel or Escape. Plaintext reading returns focus and mail-pane scroll position.

Analysis metadata shows only time and recorded successful-response token totals; the accounting caveat belongs in a tooltip. Keep only destination hints in the mail pane. Failed preflight opens repair controls at the top of Settings → Organizing rules, and successful save/recheck returns to mail. Remove the bottom privacy text and shortcut buttons from both workspace and settings; Privacy & records remains in settings navigation.

Highest complete matching non-keep action wins: delete > junk > move > archive > all flag actions. Highest-level different actions/destinations require review. Ordinary exceptions apply only to their own rule; only explicit keep-action rules protect globally, and uncertain global protection requires review. Ordinary uncertainty cannot veto a complete match. Version 8 invalidates older rule authorization, not manual processing or undo; current rule semantics apply directly without a legacy acknowledgement, and saved rule text remains unchanged. AI badges never change because an operation succeeds. Latest-operation issues come from the saved batch. Active operation IDs distinguish neutral in-progress checking from final unresolved outcomes; do not label an ongoing automatic check as a failure or offer manual refresh before it finishes. Already confirmed rows retain their success state. Unknown final outcomes offer read-only verification.

Local Analysis details are independent of plaintext reading and require no mailbox/model call. Separate historical rules, raw condition/time answers and probabilities, program decisions, and request attempts. Basic evidence excludes body context; opt-in encrypted full traces show the actual request/response, never a reconstructed substitute. Keep only the newest batch for up to 7 days/50 MiB, with a 1 MiB response limit and no credentials. Clean expired traces on startup/access, or next startup when closed. Disabling or clearing traces preserves judgments and undo. Show missing evidence and unknown usage explicitly. Failed-analysis retry requires the same input hash/account/rules/scope within 7 days, only for unfinished judgments; append attempts rather than overwrite history. Successful and merely low-confidence judgments cannot use retry.
