# JevClean 界面文案对照表

这套文案让个人邮箱整理用户看懂三件事：在哪里设置，分析结果是什么意思，确认后邮件会怎样处理。功能、四类结果的成员、处理范围、概率门槛及撤销限制均不改。这是已确认并落实到源码的中文文案对照表。英文显示采用对应名称，规则条件和原始数据保留。

名称和状态的固定部分为2至4字；界面说明每句最多20字，必要信息可以分成多句，标点和空格也计入。邮件名称、规则名称、文件夹路径、数量及日期保持原样，不按字数裁剪。品牌和计量单位保持准确，不把服务用量换成字数或费用。

本表按当前界面源码盘点，共621条候选。相同原文在相同含义下采用同一新文案；原本清楚的名称保留。语言文件中的旧入口不作为新增功能。

## 文案原则

把《Don't Make Me Think》的常用名称、易扫读和删去多余文字，落实到直说动作与下一步。[出版社试读](https://www.peachpit.com/content/images/9780321965516/samplepages/0321965515.pdf)

把《写给大家看的设计书》的对比、重复、对齐和亲密性，落实为同级名称同一种句式、同一功能同一个词、分析判断与处理结果明确区分、说明紧跟对应操作；本轮不改布局。[出版社介绍](https://www.peachpit.com/store/non-designers-design-book-9780321193858)

## 已确认的改写范围

用户已确认以下两项边界：

1. 保留规则条件和原始数据，只改菜单、按钮、字段名和界面说明。规则条件、模型提问、原始请求和返回内容不改写。规则输入框中的完整条件示例属于语义内容，标为“保留原文”，不按20字缩写。
2. 界面说明按每句最多20字计算，必要信息分句保留。“分句说明”已按此要求定稿，不删去删除、发送邮件和清除记录的必要后果。

本表共621条，含36条分句说明及1条保留原文的条件示例。所有条目均已落实或按表保留。核心和本地服务实现未变；程序提示仅在显示层改写，历史记录不回写。验证结果见 README 中本轮记录。

## 应用时保留的边界

- 同一动作的工具栏、规则表单、确认按钮和结果提示使用同一名称。数量留在弹窗现有摘要中；固定按钮名为2至4字，不因省字遗漏实际处理封数。
- “符合规则”不等于已经整理，“待查看”不等于失败，“核对结果”不等于重试；实际结果仍独立展示。
- 保留“删除移入垃圾箱”“确认后才修改邮箱”“只有最近一次可撤销”等后果。必要说明用多句短句保留，每句最多20字。
- 规则名称及条件属于用户内容。预设名称建议仅适用于首次配置的展示；不自动重命名已保存规则，也不修改模型提问及历史快照。
- 原始邮件、请求、返回、分数、计量单位及错误代码保持原样。这里改的是入口名称和说明，详细数据仍可查看。
- 不增删页面、按钮或功能，不增加自动执行，不重跑分析，不连接真实邮箱。
