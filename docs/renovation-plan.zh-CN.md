# JevClean 改造方案

状态：实施方案。各项实际验证结果记录在 README；本文件不把设计目标写成已通过的验收。

## 产品目标

面向个人邮箱用户的通用 IMAP 邮件 AI 清理工具。用户只需配置邮箱和自己的 Jev API key，勾选预设规则或用自然语言描述新规则，选择每条规则的一个动作，分析并确认执行。预设与自定义走相同判断流程；增加场景不要求新增业务代码。

核心范围只有：通用 IMAP、可勾选可编辑的自然语言规则、Jev 判断、简单操作界面，以及日志、隐私、恢复等必要后台能力。

## 规则与 AI

- 初始规则：广告推广、过期验证码、过期活动、陈旧通知。前三条默认启用，第四条可选。
- 预设描述统一明确主要用途、时间条件和保留例外：验证码附带安全提醒不等于独立安全告警，凭证附带推广仍是凭证，活动介绍与报名邀请区分结束／截止时间，自动通知中的通用按钮不代表待办。只通过自然语言表达这些边界；未编辑过的旧预设兼容升级，用户改写与勾选状态保留。
- 每条规则保存标识、名称、自然语言条件、启用状态及一个动作；仅移动另选目标文件夹。动作包括删除（垃圾箱）、归档、移动、垃圾邮件、已读／未读、星标／取消星标及保留，不提供动作链或优先级编辑器。自定义规则填写名称和描述，不要求填写筛选字段、运算符或正则；新增规则排在最上面。
- 去留的语义由 Jev 判断。每封邮件逐条判断规则匹配、明确保留条件和证据不足情况；同一发件人的邮件分别处理。
- 将收件时间、当前时间、已计算的邮件年龄与必要的文本提供给 Jev。涉及正文中的截止日期或相对有效期时，Jev 选择相关时间证据，代码验证日期并计算是否过期。没有可信时间依据时保留。
- Jev 返回结构化判断而不是自由文本或可执行指令。界面直接显示动作名、命中规则与邮件预览，不加“建议”前缀。明确保留优先，低把握保留与缺失证据显示不确定。完整匹配的非保留动作按删除 > 垃圾邮件 > 移动 > 归档 > 标记操作取最高优先级；最高级别中的相同动作／目标合并，不同动作／目标需确认。冲突时只允许从该级别已完整匹配的选项中选择一个。
- 置信度与文本上限是内部参数，不再提供高级调参界面。接口异常、文本不完整、证据缺失或判断不确定时保留。
- 取消规则勾选会改变请求内容；修改规则后，原结果不能沿用旧规则清理。

## 界面

单页工作流为：基础配置（API → 语言 → 邮箱）→ 左栏设置文件夹、范围和过滤规则 → 启动分析 → 查看分类并整理／手动处理 → 明确确认 → 最近批次核对与撤销。PreVibe 灰蓝风格保留，左侧分析栏常驻、独立滚动，无收起／展开；规则的名称、完整条件和动作全部展示。启动分析常驻左栏底部，内部完成读取与 Jev 判断，移除独立读取与双路径入口。

右侧邮件上方常驻删除、移动、归档、垃圾邮件、已读／未读、星标／取消星标八个手动动作及「整理」。结果固定为命中规则、需确认、未命中规则、全部。有效分析默认勾选可执行命中邮件，可手动取消；整理只在命中页及满足执行门槛时可用，其他页禁用，手动按钮仍按选择可用。整理先核对对象、动作、目标与跳过原因，再明确确认；完成状态不改变 AI 分类。切换分类清除选择，搜索保留选择并显示隐藏数量。

文件夹为多选，默认 INBOX；分析最近 X 封或全部邮件，数量按所选文件夹合计、服务器收件时间选取。保留停止分析、纯文本预览、执行／恢复进度、最近批次撤销及只读结果核对。核对查询实际位置／标记并补齐确认信息，不重复执行、不调用 Jev。日志与隐私集中在设置中。
移除四页侧栏、固定三类别范围、50 封试扫与全量两套入口，以及验证码小时数、保留天数、附件保护、发件人列表、模型、正文字符数和置信度等高级输入。

## 运行方式

项目目录和产品统一命名为 `JevClean`，继续采用 TypeScript、React、ImapFlow、mailparser 与直接 Jev HTTP API。

移除 Electron。一个 Node.js 本机进程提供静态界面与受限本地 API，连接用户邮箱和 Jev；启动时打开系统浏览器。仅监听 127.0.0.1，校验 Host/Origin 和随机会话令牌。没有项目云端、用户账户、密钥中转、遥测或外部前端资源。

源码版本提供标准 npm 启动命令。macOS 发行版提供可双击启动的应用，包含运行时与本地资源，不捆绑浏览器引擎。其他系统可从源码运行，未验证的平台不宣称已通过打包验收。

## 保留、替换和删除

| 部分 | 处理 |
| --- | --- |
| IMAP 连接、文本解析、身份校验 | 保留并补充常见服务商连接预设 |
| Jev 请求与错误处理 | 保留，按启用的自然语言规则动态提问 |
| 固定类别及关键词业务保护 | 替换为通用规则匹配 |
| 加密配置和恢复记录 | 保留存储边界，替换 Electron 加密适配为系统凭据库保护的本地加密 |

| Desktop / IPC / Electron 打包 | 删除并替换为本地服务、启动和轻量打包 |
| 旧文档与测试 | 同步新行为，保留有意义的协议和恢复测试 |

## 隐私与可靠性

- 密钥和 IMAP 授权码只在本机加密保存，调用时分别发送给 Jev 和用户配置的邮箱。没有明文存储降级。
- 原始正文仅在内存中用于判断和预览，不写入运行日志；附件与远程图片不下载。必要的邮件文本会发送给 Jev，不能宣称完全离线或第三方零保留。
- 本地日志只记录应用事件、汇总数字、模型版本和请求用量，并自动限制体积。
- 分析不改变邮件已读状态。移动类动作使用可恢复移动，标记类动作只修改对应标记并保存原始值；检查账号、邮件身份与当前规则，记录操作与目标 UID。操作结果不确定时不盲目重试。恢复所需的元数据加密保存。
- IMAP 密码/授权码登录与安全移动能力分别验收；仅 OAuth 账号和不支持安全移动的服务器明确提示限制，不把服务器预设当作实际兼容证据。
- 原目录与旧 Electron 配置有不同加密格式；不擅自读取或迁移用户凭据，新版重新填写两组凭据。

## 验收

1. 新增场景只需新增规则文字；修改、禁用规则确实改变请求和结果。
2. 同一发件人的广告与有用邮件可分别处理；保留条件、时间不确定与失败路径得到验证；规则之间不因无关的不确定结果相互否决。
3. 本地 API 拒绝其他网页、错误令牌和伪造操作输入，密钥不返回前端或日志。
4. 在本地 TLS IMAP 测试服务器验证只读读取、实际移动、标记与恢复；界面测试覆盖真实本地 HTTP 边界。
5. 中文和英文模型质量使用可选的预先标注合成样本检查，明确参考标签是否经用户核对；不使用真实邮箱或付费 key 进行自动测试，不把 mock 测试当成模型准确率。
6. 完成类型检查、核心测试、浏览器流程、生产启动和 macOS 包体积测量。真实邮箱与真实 Jev 验收取决于用户凭据，缺少凭据时明确标为未验证。

## 调研采用方式

IMAP Cleanup Tool 验证了本机程序加浏览器界面的路径，但它的字段规则界面与按发件人批量判定不能直接满足本产品。email-cleaner 的轻量模块边界值得参考。保留已有通用模块比整体 fork 后重写 Jev 与界面更短；项目维持 MIT，不复制其他项目的实现代码。
