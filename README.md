# JevClean

Local IMAP mail organization with Jev analysis of natural-language rules and explicit manual controls. MIT licensed.

公开仓库以 2026-10-15 的完整源码、测试、文档和设计资料作为首次提交，此前私有开发历史不纳入公开分支。项目使用 [MIT 许可证](LICENSE)；密钥、真实邮件、本机运行数据和构建产物不随源码提交。

在自己的电脑上配置邮箱和 Jev API，选择分析范围与自然语言规则，启动分析后核对并整理邮件。每条规则一个动作，也可勾选邮件直接指定手动动作，两者均需明确确认。无需迁移邮箱、修改域名解析或部署云端服务。

![JevClean 邮件结果主界面](docs/images/review-example.png)

截图仅使用合成邮件和模拟模型，不代表真实 Jev 判断质量；本轮 AI 优先流程的最终截图与验证状态见实施记录。

## 功能与边界

- 通用 IMAP over TLS；提供 Gmail、QQ、163、126、iCloud、飞书服务器预设，也可自行填写。
- 可勾选、编辑、删除的自然语言规则，每条规则只配置一个动作：删除、归档、移动到文件夹、标为垃圾、标为已读／未读、添加／取消星标或保留。广告推广、验证码、过期活动默认开启，旧通知可选；自定义规则走同一条 AI 判断流程。已有规则名称和条件保持原样，新的显示名称仅用于首次配置。
- 预设按主要用途区分验证码与独立安全告警、推广与交易凭证、邀请与报名凭证、自动提醒与真实待办。默认规则仅用于首次配置；已保存的规则描述、顺序和勾选状态按原样读取，不自动升级。
- 直接调用 Jev，用户提供自己的 API key。每封邮件分别判断；条件和时间均达门槛才形成动作判断，能否执行另行检查。普通规则的排除／保留例外只约束本条，只有独立的保留动作规则才全局保护；全局保留不确定时进入需确认。多条普通完整匹配按删除 > 垃圾邮件 > 移动 > 归档 > 标记操作取最高优先级；同级不同动作或目标进入需确认，不相关规则不会否决完整匹配。没有完整命中不会自动操作。
- 设置按「分析服务」「邮箱设置」「显示语言」「管理规则」「隐私记录」分为独立页面，默认打开「分析服务」；左侧常驻分析范围和全部过滤规则，右侧为邮件工作区。两侧独立滚动，侧栏与规则列表常驻；「选文件夹」「邮件范围」「整理规则」采用同级标题，详细描述默认收起，可逐条展开，新增规则置顶。
- 单一「开始分析」入口读取所选范围并调用 Jev；界面不再提供独立读取入口。邮件上方常驻删除、移动、归档、垃圾邮件、已读／未读、星标／取消星标八个手动动作。未分类、保留、需要确认和规则冲突的已加载邮件均可勾选；手动处理不依赖 AI 门槛或规则摘要。
- 结果固定分为「符合规则」「待查看」「暂不整理」「全部邮件」；有效结果默认勾选可执行的命中邮件，可逐封取消。固定名称「整理」仅在「符合规则」页且满足执行条件时可用，打开模态窗口核对数量、动作与去向后再确认。
- 手动处理不调用 Jev，不改写原始分类。只检查用户选择的动作，展示数量与目标后确认；按规则处理只包含满足既有判断和执行条件的选中邮件。两条流程共用模态确认、进度、结果刷新和撤销；取消或 Escape 关闭弹窗并返回触发按钮，确认期间背景不可操作。
- 可选择分析最近 X 封或全部邮件；多选文件夹时按合计数量、服务器收件时间选取，只有该范围内的邮件读取正文并交给 Jev；执行用的勾选集合不限制分析范围。
- 分析前只读检查全部启用规则的动作所需文件夹与服务器能力；优先采用服务器用途标识，再以唯一精确常见名称识别。失败时进入「设置 → 管理规则」修复，不读取正文或调用 Jev；邮件区只保留已确认的动作去向提示。AI 判断与执行状态分开；补齐或修改目标后可复用原判断。
- 删除移入邮箱垃圾箱，归档与移动进入对应目标文件夹；标记动作只修改其标记。可撤销最近一批操作，重新分析或重启应用后仍保留位置／原始标记凭据。
- 显示执行／恢复进度及独立最近批次汇总。自动只读核对期间，受影响的邮件和底部进度用中性状态显示「正在确认」，隐藏异常提示和刷新按钮，已确认成功的邮件保持成功。核对结束仍未确认才显示黄色提醒、具体原因和「核对结果」；刷新只查询位置、标记和撤销记录，不重复执行、不调用 Jev。本次整理封数与文件夹邮件列表检查条数分开，刷新页面可继续查看进度。设置中的运行记录显示转入核对的原因、结果与耗时，不包含邮件文字或账号标识。
- 任务结束明确显示「分析完成」或「整理完成」及本次数量，保留到手动关闭或下一项操作。分析停止／中断、没有有效判断或部分整理失败／未确认时显示实际情况，只有全部邮件确认处理成功才提示整理完成；页面重载后接续的任务完成时同样提示。
- 当前列表搜索只查已加载主题和发件人，搜索变化会取消不匹配邮件的勾选，清空搜索不补选。工具栏保留已选数量，不另设查看已选或清除选择按钮。
- 分析元信息仅显示时间和已记录成功响应的 token 累计，不代表完整账单消耗。
- 邮件行提供独立「分析详情」，离线查看当时的规则、原始条件／时间选项概率、程序结论及每次调用的状态、耗时和已知用量，不依赖重新读取正文。缺失的用量显示未知；可选完整调用记录保存实际请求与响应，不把重建预览当作历史原件。
- 仅重试同一报告中未获得有效判断的失败邮件；须同账号、规则与范围、输入摘要一致且在 7 天内。旧尝试追加保留，不重跑已成功或仅概率不足的判断；重试可能继续消耗 Jev 额度。
- 本地加密配置与记录、系统凭据库、操作日志、停止分析及隐私说明；隐私与运行记录统一从设置进入。

**需要一个本机进程，不需要项目云端。** Node.js 提供本地 API，系统浏览器展示界面；没有 Electron、项目账号、数据库服务、遥测、密钥中转或远程前端资源。Jev 仍会收到必要的邮件文字，并使用用户的账户额度。

当前配置一个邮箱，一次可勾选多个文件夹；进度合并显示，恢复时回到各自原文件夹。没有邮件收发、后台定时任务或 OAuth 登录。密码／授权码无法登录的账号目前不兼容。删除、归档、移动和垃圾邮件操作要求 `MOVE` 和 `UIDPLUS`；标记操作不要求这些扩展。系统文件夹自动识别失败或候选不唯一时可手动选择；「垃圾箱」指邮箱中的删除目标文件夹，不是电脑废纸篓。预检不试写邮件，实际执行时仍需核对权限、邮件身份与目标。Gmail 使用 All Mail 归档时只接受 INBOX 来源；其他标签可用移动动作。这些限制不是服务商预设就能消除的。

## 开始使用

### macOS Apple Silicon

需要 macOS 13.5 或更新版本。本地生成的发行文件位于 `release/JevClean-mac-arm64.zip`。解压后双击 `JevClean.app`，它会打开系统浏览器。该包包含独立 Node.js 运行时，使用者无需安装开发环境。

更新已有安装时，先等待任务结束并从应用菜单退出，再替换「应用程序」中的 `JevClean.app`，然后重新打开。`npm run build` 和 `npm run pack:mac` 不会自动更新 `/Applications`；旧服务未退出时，新启动会复用旧服务。配置、报告和撤销记录保存在原来的本地数据目录中，不随应用包替换。

当前包是本机 ad-hoc 签名，尚未通过 Apple 公证。对外分发前还需开发者签名、公证及另一台 Mac 的安装验收；当前不宣称已完成公共发行。轻量 macOS 启动器支持从 Spotlight／Finder 再次打开，唤起浏览器并复用正在运行的服务。右上角「应用菜单 → 退出应用」结束服务及启动器，之后可重新打开。分析、执行或撤销期间禁用该按钮，先停止分析或等待操作结束。

### 从源码运行

需要 Node.js 22 或更新版本，建议 Node.js 24 LTS，以及可用的系统凭据库。

```sh
npm ci
npm run build
npm start
```

启动会打开浏览器。只编译后重新运行的开发入口：`npm run dev`。终端版可按 Ctrl+C 退出，`npm start -- --no-open` 可只输出本地地址。

macOS 使用钥匙串，Windows 使用系统凭据库，Linux 必须有 Secret Service（例如 GNOME Keyring／KWallet 的兼容服务）。凭据库不可用时拒绝保存，不退回明文。Windows／Linux 源码路径存在，但本轮没有实机验收。

1. 打开设置，默认进入「分析服务」填写自己的 Jev API key；分别在「邮箱设置」「显示语言」完成邮箱和界面语言配置，保存设置并检查连接。切换页面保留未保存的配置和密钥草稿。
2. 返回工作区，在常驻左栏选择文件夹、最近 X 封或全部邮件，并勾选过滤规则。名称和动作直接展示，详细条件默认收起，可点击条内「展开」查看。通过「管理规则」新增或编辑，新规则排在最上面。
3. 同意发送必要文字，点击左栏底部「开始分析」。它会读取并分析配置范围内的邮件，不以邮件复选框为分析范围；分析前先检查启用动作的文件夹及服务器能力，失败先修复，不调用 Jev。分析不修改邮箱，重复分析可能再次消耗额度。
4. 查看「符合规则／待查看／暂不整理／全部邮件」。可执行的命中邮件默认勾选，取消不想处理的邮件后点击「整理」，在弹窗核对实际处理数量、动作和目标，再明确确认。完成状态单独显示，不改变 AI 分类；切换分类会清除选择，回到「符合规则」重新默认选中可执行项。
5. 需要自己指定操作时，勾选邮件，点击邮件区上方任一手动动作，检查数量和目标后确认。其他分类中的「整理」为灰色禁用，但手动动作仍可使用。搜索变化会取消不匹配邮件的勾选，清空搜索不补选；工具栏显示当前已选数量。
6. 「最近整理」显示真实批次结果，可刷新或撤销；上一批仍有结果未确认时，先刷新核对，再开始新批次。隐私、日志和本地数据管理集中在设置中。

详见[中文使用说明](docs/usage.zh-CN.md)，自定义域名邮箱也可继续使用原服务商，无需切换邮件系统。

## 隐私

- 邮箱密码与 API key 加密保存在本机；AES-256-GCM 解密钥匙保存在系统凭据库。网页只收到“是否已保存”，无法读回已保存密钥。
- 邮箱密码只用于用户配置的 IMAP 服务器；API key 只用于 `https://api.typesafe.ai/v1/systemone`。没有项目方代理。
- 提交必要主题、发件人地址、纯文本正文、收件时间和状态给 Jev。尽量隐藏链接路径和可识别口令／验证码，无法保证清除所有敏感信息；不宣称完全离线或第三方零保留。
- 默认不保存正文、正文上下文或服务响应原文；基本分析证据、主题、发件人及恢复凭据加密保存。附件和远程图片不下载，操作日志只存事件与汇总数字。
- 可在「隐私记录」主动开启完整调用记录，实际请求中的邮件文字及服务响应另行加密保存；仅最新批次、最长 7 天、总量 50 MiB，单响应最多 1 MiB。启动／访问时清理到期数据，关闭应用期间到期的数据下次启动清理。关闭开关或清除完整记录不影响分析结论和撤销；密钥及认证头不进入调用记录。
- 本地服务只监听 `127.0.0.1`，校验 Host、Origin 与随机会话令牌。它是单机应用，不可开放到局域网或互联网。

[完整隐私说明](docs/privacy.md)。不读取 Apple Mail 的本地邮件数据库。

## 验证与发布

```sh
npm run check          # 类型、核心／本地 HTTP／TLS IMAP 测试、生产构建
npx playwright install chromium
npm run test:ui        # 真实本地 HTTP 接口上的浏览器流程
npm run test:native    # 用临时条目检查实际系统凭据库
npm run pack:mac       # 当前 macOS 架构打包，首次下载官方运行时并核对校验和
npm run test:menu      # 打包后，用隔离服务验证实际 AppKit 菜单与安全生命周期
node scripts/smoke-package.mjs # 包内运行时、加密、重启、系统再次打开、单实例及签名检查
```

macOS 菜单栏的信封图标提供运行状态、打开、重启和退出；任务期间不能重启／退出。`--no-open` 只抑制 macOS 首次打开，之后双击或菜单「打开应用」仍会显示页面。菜单行为通过实际 AppKit 启动器和隔离服务验证；安装后另行核对实际浏览器页面，不把接口响应正常当作界面已打开。

真实模型检查需主动提供 `JEVCLEAN_JEV_KEY` 后运行 `npm run test:quality`。只发送仓库内预先标注的中文／英文合成样本，会消耗额度；未提供 key 时明确跳过。`JEVCLEAN_MAX_CALLS` 可限制请求尝试次数，默认等于案例数；失败计数、不自动重试。密钥不得写进源码或提交到 Git。
