# 核心模块

输入是经过验证的本地配置、用户规则、IMAP 数据与 Jev 返回值；输出为独立邮件列表、AI 分类和带恢复凭据的规则／手动邮件操作。详细流程见 [架构说明](../../docs/architecture.md)。

- `service.ts`：仅邮件头的独立读取、手动动作只读检查／单次确认计划、分类证据与实际操作分离、串行任务、停止分析、多文件夹合计最近 X 封／全部只读扫描、预览、启用动作只读预检、独立执行状态、目标修改复用及动作冲突选择、执行／恢复进度、独立最近批次汇总（含原报告标识及已确认操作去向）及只读位置／标记核对；调用方为本地 HTTP 服务。`saveAnalysisSettings` 只合并分析范围、文件夹、已保存规则的勾选和发送文本同意，不修改凭据或规则内容；空文件夹选择可保存，分析前拒绝。`isBusy` 返回实际任务锁，供菜单栏状态及安全退出使用。核对不调用 Jev，也不重复执行；向界面返回当前进程中与账号／密码匹配的最近连接验证状态，重启清空，非持续连接。
- `actions.ts`：删除、归档、垃圾邮件和移动的目标解析；优先显式映射或唯一特殊用途文件夹，服务器用途标识优先，其次唯一精确常见名称；多候选要求手动选择，不创建或用子串猜测系统文件夹。Gmail 的 All Mail 归档仅接受 INBOX 来源。
- `mailbox.ts`：严格 TLS、MIME 文本读取、仅 UID／服务器收件时间的分批范围选取、仅邮件头的身份查询、账号／邮件身份、安全 UID MOVE 能力。
- `classifier.ts`：条件题统一 match／not_match／uncertain，和时间题分开；普通规则的排除／保留例外只约束本条，只有 action=keep 规则全局保护。条件选项低于0.80（含 not_match）或直接 uncertain 为本条不确定；普通不确定不否决其他完整匹配，全局保留不确定阻止按规则处理。动作与目标不作为模型问题字段；保留原始回答，完整动作交给 rules 合并。
- `privacy.ts`：文本最小化、通用日期／时长候选枚举、收件年龄与邮件指纹；不承担邮件语义分类。
- `jev.ts`：固定 HTTPS 接口、超时／重试、结构与概率验证、脱敏错误；逐 attempt 通知发送／成功／失败／取消、耗时、HTTP 状态及已知用量。原响应仅进入主动开启的完整诊断，不进入普通错误或日志；单响应上限1 MiB，截断不采纳，密钥不进入记录。
- `rules.ts`：固定模型、0.80门槛、完整策略与独立语义摘要（排除目标；条件、动作、账号及范围仍参与）。mergeRuleActions 统一初判与目标重建：删除 > 垃圾邮件 > 移动 > 归档 > 标记操作，同级不同动作／目标保留冲突，较低级别不能打破冲突。先处理显式全局保留。摘要版本8使旧按规则报告失效，诊断开关不入摘要；不影响手动授权及撤销。
- `storage.ts`：按当前契约读取加密配置／最近报告／独立最近操作；默认基本快照无正文上下文。完整trace主动开启后独立加密，仅最新批、7天、50 MiB；启动／访问清理过期数据，应用关闭期间到期则下次启动清理。关闭或清除trace不删除撤销；不覆盖用户规则、不补回已删规则、不把缺失旧证据补造成新授权。`Cipher` 由本地运行层提供，测试可注入。

`service.recordedEvaluator` 在发送前保存实际输入摘要、当时规则与去正文上下文的问题快照；完整request/response仅放独立trace。保存失败停止，已知usage按尝试记录，缺失为未知。不设旧版规则作用范围标记或确认步骤，不自动升级规则描述或补写报告语义摘要。`analysisTrace` 按当前report/record标识只读本地证据，无IMAP或Jev；`retryAnalysis` 仅处理未获有效判断且未执行、有v8 inputHash、7天内的失败记录，复核同账号／规则／范围、UIDVALIDITY／指纹与原时间构造的输入摘要，变化则拒绝。重试追加attempt，不覆盖旧尝试，不重跑成功或低把握判断。

整理／撤销进入自动核对时发布 `checking` 阶段。动作进度携带当前显示报告的 `operationIds`，按同账号、指纹及已记录物理位置关联；不能仅按相同指纹把副本视为本批对象。可注入 `OperationDiagnostic` 回调记录固定原因代码、数量和核对耗时，区分缺失／不完整／不一致的移动回执、操作连接或响应异常、核对读取失败及最终身份／副本／缺失问题；不传记录 ID、邮件内容、文件夹或第三方原始错误，回调失败不改变动作结果。`Progress.processed/total` 始终按该阶段要处理的邮件计数；`operationTotal` 保留本次操作数量。读取相关文件夹邮件头的数量独立放在 `folderCheck`，不得作为已处理封数；检查不新增邮件动作、正文读取或 Jev 调用。

`CleanupSummary.issues` 仅从独立最近操作记录生成异常项（记录标识、主题、执行状态及操作原因），不能从当前邮件列表推导最近批次明细。当前报告可能包含更早批次的失败，也可能已被重新读取或分析替换。旧操作记录缺少错误说明时提供保守的执行状态提示，不把 AI 分类原因当成执行失败原因。

维护接口时同步 `src/shared/contracts.ts`、HTTP 路由、界面和相关测试。模型模拟只能验证调用及执行机制，不能证明语义准确率。

`readMail` 是内部独立邮件头读取能力，当前界面不提供独立读取入口。它不需要规则、Jev 密钥或正文发送同意；未分类使用独立 category。同策略且位置、相关标记未变化时复用已有分类，不生成新的 AI 授权。`checkManual` 仅检查所选动作，生成进程内计划；`executeManual` 只接受该计划标识，复查账号、列表快照、目标和邮件身份。手动意图单独保存在 `MailRecord.operation`，不伪造模型概率、不改写规则判断。原始标记以实际执行前读取值记录。新批次不得覆盖未确认的上一批，先只读刷新。规则路径仍核对语义摘要和门槛；两条路径共用安全执行、进度、结果和撤销。

跨列表同步必须同时核对账号、邮件头元数据指纹和完整位置（文件夹、UIDVALIDITY、UID），不能以指纹合并副本。可选 `MailRecord.operationLocations` 保留本批操作已经记录的位置，避免撤销产生新 UID 后丢失旧位置关联；旧记录继续使用已有来源和完整目标回执，不按指纹补造映射。未知结果只更新关联行的阻断状态，不覆盖新列表观察到的位置；缺 MOVE 回执时，仅将已知目标文件夹及 UIDVALIDITY 内的同指纹邮件视为待核对候选，不认定为同一物理邮件。最近操作已落盘而旧报告仍待处理时，重读仍须阻断对应邮件，不能因复用分类放行。回归见 `tests/message-identity.test.ts`。
